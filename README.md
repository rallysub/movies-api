# Movies API

Асинхронное REST API-приложение для каталога фильмов. Проект создан в рамках воркшопа и позволяет получать список фильмов, просматривать отдельные записи, добавлять, обновлять и удалять фильмы.

## Основные возможности

- Получение списка фильмов с пагинацией (`limit`, `offset`).
- Получение фильма по идентификатору.
- Создание фильма.
- Полное обновление фильма (`PUT`).
- Частичное обновление фильма (`PATCH`).
- Удаление фильма.
- Валидация полей фильма с помощью Pydantic.
- Интерактивная документация Swagger UI и ReDoc от FastAPI.

## Технологический стек

- Python
- FastAPI
- Uvicorn
- SQLAlchemy 2.x (асинхронный ORM)
- SQLite и aiosqlite
- Pydantic 2
- Alembic (миграции)

## Основные эндпоинты

Базовый префикс: `/movies`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | Проверка доступности API |
| GET | `/movies/` | Получить список фильмов |
| GET | `/movies/{movie_id}` | Получить фильм по ID |
| POST | `/movies/` | Создать фильм |
| PUT | `/movies/{movie_id}` | Полностью обновить фильм |
| PATCH | `/movies/{movie_id}` | Частично обновить фильм |
| DELETE | `/movies/{movie_id}` | Удалить фильм |

Для несуществующего фильма предусмотрен ответ `404` с сообщением «Фильм не найден».

Пример тела запроса для создания фильма:

```json
{
  "title": "The Matrix",
  "genre": "Sci-Fi",
  "rating": 8.7,
  "year": 1999
}
```

## Фильтрация и сортировка

В коде репозитория предусмотрены параметры:

- `year_min` — минимальный год выпуска;
- `year_max` — максимальный год выпуска;
- `min_rating` — минимальный рейтинг;
- `order_by` — поле и направление сортировки;
- `limit` — количество записей (ограничивается диапазоном 1–100);
- `offset` — смещение для пагинации.

Для `order_by` доступны `title`, `-title`, `year`, `-year`, `rating`, `-rating`, `id`, `-id`. По умолчанию предполагается сортировка по рейтингу по убыванию.

**Примечание:** в текущем обработчике списка (`src/routers/movies.py`) параметры фильтрации и сортировки объявлены, но в вызов репозитория передаются только `limit` и `offset`. Поэтому фильтры и сортировка пока не применяются через HTTP-запрос. Для их полноценной работы нужно передать все параметры в `repo.get_list_movies` в правильном порядке или по именам.

## Модель данных

Таблица `movies` содержит следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `id` | Integer | Первичный ключ, идентификатор фильма |
| `title` | String | Название фильма |
| `genre` | String | Жанр |
| `rating` | Float | Рейтинг |
| `year` | Integer | Год выпуска |

Pydantic-схемы проверяют входные данные: название — от 2 до 200 символов, жанр — от 2 до 100 символов, рейтинг — от 0 до 10, год — от 1888 до текущего года.

## Ограничения базы данных

- `id` — первичный ключ.
- `title`, `genre`, `rating` и `year` объявлены как `NOT NULL`.
- Для `id` и `title` создаются индексы.
- SQLite используется как база данных; подключение приложения настроено через `sqlite+aiosqlite:///./show.db`.

**Важно:** ограничения диапазона рейтинга и года проверяются схемой Pydantic. В текущем файле ORM-модели ограничение `CheckConstraint` записано в переменную `__table_args_` (с одним завершающим подчёркиванием), а в миграции эти `CHECK`-ограничения отсутствуют. Поэтому сейчас они не являются ограничениями самой базы данных.
